- 2026-09-17 — FluidAudio pinned to exact version 0.15.7 (latest tag at time of M0) — SPEC §10.1 asks for an exact pin; bump deliberately in M4 after checking release notes — Claude Code
- 2026-09-17 — `AppServices.live()` returns fakes until each milestone lands its real service — Lets the app launch and the UI be built against protocols from M0; each milestone swaps one service — Claude Code
- 2026-09-17 — Building with Xcode 26.6 / iOS 26.5 SDK until Xcode 27 ships — That is what is installed; nothing through M4 needs iOS 27 APIs. M5 must gate `SystemLanguageModel.contextSize` and `tokenCount(for:)` behind `#available(iOS 27, *)` and also compile-time `#if canImport` checks if the SDK still lacks them — Jeremy / Claude Code
- 2026-09-17 — M1 recorder uses the classic `AVAudioEngine.connect`, `installTap`, and `AVAudioSession.interruptionNotification` APIs — Apple's docs mark them deprecated in iOS 27 in favour of `connectNode`, `AVAudioSession.InterruptionContext`, and friends, but those replacements are iOS 27-only and absent from the iOS 26.5 SDK we build with. Revisit when Xcode 27 is in use: gate the new calls behind `#available(iOS 27, *)` — Claude Code
- 2026-09-17 — Recorder graph is a tap on `inputNode` in its native format, converted per buffer with `AVAudioConverter` to mono 44.1 kHz float; no output path — First attempt routed input → mixer → muted main mixer and tapped the mixer, and on device the file came out silent. Tapping the input directly is Apple's documented pattern and doesn't depend on the engine pulling audio through an output — Claude Code
- 2026-09-17 — Launch recovery marks an interrupted recording `.failed` (not `.recorded`) when its audio file is missing or unreadable — SPEC §8.2 says mark `.recorded`, but a row that can't play or transcribe would just fail later with a worse message; readable files are marked `.recorded` as specified — Claude Code
- 2026-09-17 — Capture format is AAC in an ADTS stream (`audio.aac`), not AAC in CAF as SPEC §8.2 says — Verified on device: a force-quit mid-recording left the CAF/AAC file unreadable (181 KB on disk, AVAudioFile refused it) because Core Audio writes the CAF packet table only on close. ADTS frames each carry a header, so a truncated file plays up to the last whole frame; same codec, sample rate, and ~64 kbps. Unit test truncates an ADTS file and reads it back. Rows created before this change keep their `audio.caf` name and still resolve — Jeremy / Claude Code
- 2026-09-17 — Share-sheet import uses document types + `onOpenURL` (system copies the file to Documents/Inbox), not a Share Extension — Same user-visible result ("VeraFlow" in the share sheet / "Open in"), no second app target, no app group, no extra signing. Revisit only if a "share without leaving the other app" flow is wanted — Jeremy / Claude Code
- 2026-09-17 — Imported files keep their original container (`audio.m4a`, `audio.wav`, ...) rather than being transcoded to ADTS — The crash-safety reason for ADTS applies to live capture only; playback and transcription read any of the supported containers, and copying is instant where transcoding a 60-minute file is not — Claude Code

- 2026-09-17 — Every restart of capture (Resume, configuration change, media-services reset) discards the `AVAudioEngine`, builds a new one, re-reads the input node's output format (retrying briefly while it reads 0 Hz after a route change), and only then installs a tap — The 90-minute device test was interrupted at 43:42 and crashed on Resume. The crash log shows an Objective-C exception inside `installTap`, reached from the configuration-change handler re-tapping an engine that Resume had just started. `installTap` cannot be caught from Swift, so the conditions it rejects are checked first and the engine is always stopped before re-tapping; a bad state degrades to "Paused, tap Resume" instead of a crash. A fresh engine is required, not just a stopped one: re-tapping a running engine is what raised the exception. A first version also demanded that the node's output format equal the hardware format; on device those legitimately differ after a Bluetooth switch (session at the headset's 16 kHz, hardware reporting the iPhone mic's 48 kHz), which left Resume stuck, so the tap simply uses the node's output format as Apple's samples do. The interruption reason is now logged so the next pause can be explained — Claude Code
- 2026-09-17 — Playback duration comes from `AudioFileInfo.duration(of:)` (frame count), not `AVAudioPlayer.duration` — For ADTS streams the player's duration is a bit-rate estimate and showed 42:22 for a 43:42 recording; the frame count matches the recorder's timer — Claude Code
- 2026-09-17 — Recording Live Activity (Lock Screen banner + Dynamic Island: timer, Recording/Paused, bookmark count) is built in M1, status only, as a `VeraFlowWidgets` app-extension target sharing `Shared/RecordingActivityAttributes.swift` with the app — SPEC §16 lists it as a v1.1 stretch item; Jeremy asked for it after the first long device test. Status only (no Lock Screen buttons) keeps it to ActivityKit + one widget target; buttons would add App Intents and are a later step. The extension has no network, no app group, and no push token — Jeremy / Claude Code
