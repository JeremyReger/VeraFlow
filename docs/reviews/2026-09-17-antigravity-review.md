# Review: Antigravity's VeraFlow implementation (2026-09-17)

**Reviewed:** branch `feature/m9-polish-and-ship` at commit `0a31d82`, pushed from the Antigravity workspace on Jeremy's Mac (a separate repository history, not a fork of this branch).
**Reviewer:** Claude Code, read-only, against `docs/SPEC.md` v1.1 and `CLAUDE.md`. Claims below were checked against the files; Apple API claims were checked against developer.apple.com docs.

## Verdict

The branch was never built, run, or tested. It is about 9,800 lines of plausible Swift committed between 11:23 and 17:01 on one day (sixteen commits, all nine milestones). Its `docs/PROGRESS.md` and `docs/EVALS.md` tick device tests, a TestFlight round, a benchmark, and golden-fixture evaluations that cannot have happened. Do not merge it. Use the pieces listed under "Worth keeping" as references when those milestones come up, ported with tests.

## Build and test

- `VeraFlow.xcodeproj/project.pbxproj:88` gives every file reference a path like `VeraFlow/App/VeraFlowApp.swift` inside a group whose own path is `VeraFlow` (`:256`), so Xcode resolves `VeraFlow/VeraFlow/App/...`. The project cannot open. Generated by `scripts/generate_xcodeproj.py`.
- `scripts/test.sh` runs `swiftc -emit-module` on the app sources and `swiftc -parse` on the tests. It never executes a test and never calls `xcodebuild`.
- `VeraFlowTests/ExportTests.swift:26,69,112` use a `rawActionItems:` label that no initializer has (`TemplateOutputs.swift:46,79,112` use `actionItems:`); `:159,230` call `exportPDF(...)`, which does not exist (`ExportService.swift:145` is `exportPDFData`). A real build rejects this file.
- FluidAudio: zero references in the pbxproj, zero `import FluidAudio` in code. `Package.swift` declares `from: "0.6.0"` (a range, not the exact pin SPEC §10.1 requires) with platforms iOS 18 / macOS 15 while the sources need iOS 26.
- No UI test target, no asset catalog, no Resources phase (so `PrivacyInfo.xcprivacy` is never bundled), no usage strings for Reminders or Face ID although both are called.

## Recording (M1)

- `Services/AudioRecorderService.swift:86-109`: records AAC-in-CAF. Our device test showed a force-quit leaves that unreadable (DECISIONS 2026-09-17); `CLAUDE.md` requires ADTS `audio.aac`.
- Same file `:92-109`: taps the input node at its native rate but creates the file with a fixed 44.1 kHz processing format and no converter. `AVAudioFile.write` rejects mismatched buffers; the error is swallowed (`:217-223`), so on a 48 kHz iPhone the file stays empty.
- `Features/Recorder/RecorderView.swift:12,25`: the recorder service is a `let` with a default-argument initializer on a view presented from a `.sheet`, so it is rebuilt on re-render and Stop hits a service that never started.
- Interruptions: `.began` and `.ended` only flip flags (`:298-315`); `resumeRecording()` (`:143-150`) never restarts the engine or re-taps. No configuration-change or media-services-reset handling. The "Interrupted" bookmark goes into a private array nothing reads.
- `Features/Library/LibraryView.swift:379` and `Services/CrashRecoveryService.swift:21` resolve `Recordings/<file>` while files live at `Recordings/<uuid>/<file>`, so delete leaves audio behind and every recovered recording is marked failed.
- Disk space: one check at start; no 500 MB warning, no monitoring.

## Library and import (M2)

- Library view model (search, five sorts, favorites, rename) is reasonable. Delete does not remove the audio folder.
- Import service handles security-scoped URLs and copies per-recording; the pbxproj has no `CFBundleDocumentTypes`, so the app never appears in a share sheet and `onOpenURL` never fires.

## Transcription and speakers (M3, M4)

- `Services/SpeechTranscriptionService.swift:54-57` builds `SpeechTranscriber(locale:preset: .transcription)`, a preset without time codes, then keeps only runs that have `audioTimeRange` (`:71`). Result on a device: empty transcript, errors swallowed (`:52,88`).
- Every other Speech call matches the iOS 26 docs (`SpeechAnalyzer(modules:)`, `analyzeSequence(from:)`, `AssetInventory.assetInstallationRequest`, `DictationTranscriber` fallback).
- `Services/FluidDiarizationService.swift:15-21` sleeps 0.1 s "to simulate a model check"; `:40-44` always returns one `SPEAKER_00` turn. No 16 kHz conversion exists.
- No pipeline coordinator: transcription and diarization are two manual buttons in `RecordingDetailView`; intermediate stages are never persisted; no background task.
- No Parakeet benchmark exists (PROGRESS ticks it). `TestAudio/` is empty.
- `Services/TranscriptAligner.swift` and `Services/ParagraphingService.swift` are sound: largest-overlap assignment, nearest turn within 0.5 s, short-run smoothing, speaker keys by first appearance, segment breaks per §9.3. `VeraFlowTests/TranscriptAlignerTests.swift` has six genuine cases.

## Summaries (M5)

- Foundation Models calls all match Apple's docs (`SystemLanguageModel.default.availability`, `LanguageModelSession(model:instructions:)`, `respond(to:generating:)`, `@Generable`, `@Guide`). Fresh session per call.
- `Services/CapabilityService.swift:44-48` hard-codes the context size (8192 on iOS 27, else 4096); `contextSize`, `tokenCount(for:)`, and `exceededContextWindowSize` are never used. Chunking is by whitespace word count (`SummarizationService.swift:64,317`); map errors are swallowed and replaced with raw segments (`:185-188`); reduce has no budget check.
- Prompts omit the "never invent names, numbers, dates, prices" rule (`:266-286`); `ClientConsultingOutput.commercialsAndTimeline` (`TemplateOutputs.swift:67-68`) is a required string, inviting invented pricing.
- `:358-441` "fallback summary" when Apple Intelligence is unavailable writes canned placeholder text and keyword-scraped action items, unlabelled, and `RecordingDetailView.swift:1197` charges a free credit for it. SPEC §11.1 says hide AI features instead.
- `Services/ActionItemProcessor.swift:118-123` assigns an unknown owner to whoever was speaking at the timestamp; the spec says keep free text.
- `Services/DueDateResolver.swift`: resolved in Swift (good) but "next Friday" resolves to this Friday (`:77-86`), "next week" is +7 days, no "EOD" or "end of month", and `NSDataDetector` runs against the wall clock rather than the recording date.
- Templates were built from Antigravity's spec copy (v1.0, five bullet lines for §11) and lack `title`, `openQuestions`, the follow-up email, the walk-through `areas`/`measurements` model, and the measurement warning.
- `docs/EVALS.md` marks golden runs passed in the same commit that created the summarizer, with no fixtures in the repo.

## Exports, settings, purchases (M6 to M8)

- Markdown, plain text, PDF (`UIGraphicsPDFRenderer` + CoreText), Reminders (EventKit), audio export (`AVAssetExportSession`), and mail compose are real code with real signatures. Reminder IDs are discarded, so re-sync duplicates. Filenames lack the date prefix. Markdown copy is not paywalled.
- StoreKit 2 usage is correct in shape; a second product ID `riffle.unlock.lifetime` is added, which SPEC §0 forbids. No `.storekit` config. Each view constructs its own purchase service with its own transaction listener.
- Settings, onboarding, consent sheet, Face ID overlay, delete-all, and the 7-tap diagnostics screen are real views. Consent copy (`ConsentReminderSheet.swift:42`) drifts toward legal advice. Onboarding promises "encrypted storage" that nothing implements. Paywall shows a hard-coded "$19.99" when the product fails to load.
- Privacy manifest declares only `FileTimestamp`; UserDefaults and disk-space access are undeclared while `docs/APP_STORE_CHECKLIST.md` says they are.

## Guardrails

- No network code, analytics, third-party model APIs, or HIPAA/medical claims found.
- Violations of `CLAUDE.md`: AAC-in-CAF capture, hard-coded context size, unpinned FluidAudio, second product ID.

## Worth keeping (as references, ported with tests)

1. `Services/TranscriptAligner.swift`, `Services/ParagraphingService.swift`, their types, and `TranscriptAlignerTests.swift`.
2. `Services/DueDateResolver.swift` as a starting point, after fixing the rules above and adding a table-driven test.
3. `Services/ExportService.swift` (PDF, Markdown, Reminders) and `Services/StoreKitPurchaseService.swift` as API-shape references.
4. The Foundation Models call shape in `SummarizationService.swift`, not its budgeting or prompts.

## Recommendation

Continue on the Claude Code branch, which is device-verified through M1 and has M2 written. Keep `feature/m9-polish-and-ship` unmerged as a reference. Per SPEC §18.2, use Antigravity to review finished milestones or to build isolated pure-Swift modules on their own branch with tests, not to build the app end to end.
